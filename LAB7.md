# Лабораторная работа 7

## Что реализовано

Первая сущность — пользователь с полным CRUD. PUT заменяет все изменяемые
публичные поля пользователя, email и displayName. Пароль задаётся при создании,
хранится как scrypt-хеш, в ответ не включается. Вторая сущность — опрос,
связанный с создателем через creator_id. Реализованы создание черновика с вопросами,
чтение по UUID и публикация. Все операции доступны из Swagger.

## Слои и зависимости

`resource_controller.py` разбирает DTO, вызывает сервис, создаёт DTO ответа и
устанавливает HTTP-заголовки. В нём нет SQL и правил публикации.
`UserService` получает UserRepository через конструктор. `SurveyService`
получает фабрику транзакционных сессий и источник времени. В сервисах
используются доменные модели и ошибки, объекты FastAPI не передаются.

`session_factory` соединяет уже существующий пул с репозиториями. Создание
опроса, его вопросов и вариантов ответа выполняется в одной транзакции.
При сбое транзакция откатывается целиком. Публикация читает опрос с
`SELECT ... FOR UPDATE`, проверяет правила и обновляет статус до фиксации
транзакции. Два параллельных запроса публикации получают 200 и 409.
Новые API-операции изменения вопросов в этой работе не добавлены.

`errors.py` в контроллерах — единое место перевода доменных ошибок в HTTP.
Некорректные UUID, JSON и DTO тоже получают 400 и общую структуру
`code`, `message`, `timestamp`. Непредвиденная ошибка получает 500
с безопасным сообщением. Обработчик health сохраняет поведение 200/503 из ЛР 5.

## Правила и ошибки

| Правило | Ошибка | HTTP |
|---|---|---|
| Создатель опроса должен существовать | ErrNotFound | 404 |
| Название после удаления крайних пробелов содержит 3–200 символов | ErrInvalidInput | 400 |
| Позиции вопросов положительны и уникальны в опросе | ErrInvalidInput | 400 |
| Публиковать можно только draft | ErrConflict | 409 |
| Для публикации нужен хотя бы один вопрос | ErrInvalidInput | 400 |
| Вопрос с выбором для публикации имеет минимум два варианта | ErrInvalidInput | 400 |
| Текстовый вопрос не содержит вариантов выбора | ErrInvalidInput | 400 |
| Email пользователя уникален | ErrAlreadyExists | 409 |
| Пользователь со связанным опросом защищён от удаления | ErrConflict | 409 |

Черновик может быть пустым или содержать незавершённый вопрос с выбором.
Публикация такого черновика возвращает 400. В DTO ограничены длины и размеры
коллекций, сервис повторно проверяет бизнес-инварианты при прямом вызове.

## Эндпоинты

| Метод | Путь | Успех | Основные ошибки |
|---|---|---|---|
| POST | /api/v1/users | 201 и Location | 400, 409 |
| GET | /api/v1/users?limit=2&offset=0 | 200 | 400 |
| GET | /api/v1/users/{id} | 200 | 400, 404 |
| PUT | /api/v1/users/{id} | 200 | 400, 404, 409 |
| DELETE | /api/v1/users/{id} | 204 без тела | 400, 404, 409 |
| POST | /api/v1/surveys | 201 и Location | 400, 404, 409 |
| GET | /api/v1/surveys/{id} | 200 | 400, 404 |
| POST | /api/v1/surveys/{id}/publish | 200 | 400, 404, 409 |

Для всех операций непредвиденные сбои возвращают 500. В Swagger показываются
работающие маршруты и DTO. В рамках ЛР 7 контракт ЛР 2 обновлён вместе с кодом.
Аутентификация и выдача JWT в этой версии не реализованы, UUID создателя
задаётся в теле запроса. Смена пароля через PUT не выполняется.

## Ручной показ через Swagger

Запуск и команда модульных тестов находятся в разделе ЛР 7 в README.
Открой http://127.0.0.1:8080/docs. UUID из ответов копируй в последующие запросы.

1. POST /api/v1/users с уникальным email, например:

   ```json
   {"email":"lab7-demo@example.test","password":"DemoPassword123","displayName":"Student"}
   ```

   Покажи 201, Location и отсутствие пароля и хеша в ответе. Сохрани id пользователя.
   При повторном показе используй новый email или удали прежнего несвязанного пользователя.

2. GET /api/v1/users с limit=2. Покажи не более двух записей.
   PUT /api/v1/users/{id} с email и новым displayName возвращает 200.
   GET /api/v1/users/00000000-0000-0000-0000-000000000000 возвращает 404.

3. Создай опрос через POST /api/v1/surveys:

   ```json
   {
     "creatorId":"UUID_ПОЛЬЗОВАТЕЛЯ",
     "title":"Оценка сервиса",
     "description":"Опрос для демонстрации ЛР 7",
     "questions":[
       {"text":"Как вам сервис?","type":"text","position":1,"isRequired":true}
     ]
   }
   ```

   Покажи 201, Location, status=draft и GET по UUID полученного опроса.

4. Для нарушения правила создай второй опрос с questions=[] и попробуй
   POST /api/v1/surveys/{id}/publish. Будет 400 с объяснением.

5. Опубликуй первый опрос. Будет 200, status=published и publishedAt.
   Повтори ту же операцию — получишь 409. Правила находятся в SurveyService.publish.

6. Для DELETE создай отдельного пользователя без опросов. Удали его — будет
   204 с пустым телом. Повторный GET вернёт 404. Удаление создателя опросов
   вернёт 409 из-за внешнего ключа. Образовавшиеся опросы остаются в учебной базе.

## Приёмочные проверки задания

Проверочный скрипт `tests/check_lab7.py` выполняет П1–П9 и дополнительные
проверки, создавая свои email со случайным суффиксом. Запускай его на отдельной
учебной базе. Он не очищает создателя и опросы после демонстрации.

| Проверка | Сценарий | Проверенный результат |
|---|---|---|
| П1 | Создание пользователя | 201, Location, UUID |
| П2 | Список limit=2 | 200, длина не больше двух |
| П3 | PUT пользователя | 200 |
| П4 | Неизвестный UUID | 404 |
| П5 | Создание опроса с вопросом | 201 |
| П6 | Публикация пустого опроса | 400 |
| П7 | Конфликт повторной публикации | 409 |
| П8 | Публикация и повтор | 200, затем 409 |
| П9 | Удаление пользователя без связей | 204 и пустое тело |

При разработке прошли 18 модульных проверок, 6 интеграционных проверок ЛР 6,
проверка отката частично созданного опроса и 22 приёмочные проверки HTTP. Проверка П3 в скрипте
дополнительно проверяет фактически изменённое имя пользователя. Для двух
одновременных публикаций проверен результат 200/409. Модульные проверки запускаются
без БД и без отдельного HTTP-сервера. При выполнении старых тестов пагинации
ЛР 6 нужна отдельная пустая база, поскольку они проверяют глобальный список.
